# 출력물 디자인 지침

드릴·동형 모의고사·학습지 등 **종이로 나가는 모든 PDF** 에 적용한다.
원장이 정한 것을 번호로 쌓는다. 번호는 바꾸지 않는다 — 코드 주석이 `디자인 지침 1` 처럼 번호로 가리킨다.

지침은 **코드로 강제**한다. 사람이 기억해서 지키는 것이 아니라, 정해진 자리를 거치면
저절로 지켜지게 한다. 새 지침을 받으면 ① 여기에 적고 ② 그것을 강제하는 코드 자리를 적는다.

이미 출력해 나간 것은 다시 뽑지 않는다. 지침은 **그 뒤에 만드는 것부터** 적용한다.

---

## 1. 쪽수는 아래 가운데 — `n / N` (2026-09-18)

모든 출력물의 **모든 쪽** 아래 가운데에 `3 / 37` 꼴로 찍는다. 문제지·정답지 각각 따로 센다.

**강제 자리:** [`tools/pdf_pages.py`](../tools/pdf_pages.py) `save_pdf()` / `stamp_file()`.
PDF 를 파일로 내는 코드는 전부 이것을 거친다 — `writer.write()` 를 직접 부르지 않는다.

| PDF 를 내는 곳 | 거치는 함수 |
|---|---|
| `tools/build_school_drills.py` (학교 × 과 자체드릴) | `save_pdf` |
| `tools/build_drill_pdf.py` (드릴 종류별 8권) | `save_pdf` |
| `tools/build_mock_pdf.py` (동형 모의고사) | `stamp_file` |

**왜 HTML 이 아니라 PDF 단계에서 찍는가:** Chrome 은 `@page { @bottom-center }` 를
지원하지 않고, 기본 머리글·바닥글은 날짜·URL 이 붙어 못 쓴다. 게다가 한 권은 세트
여러 개를 따로 찍어 잇기 때문에 전체 쪽수 `N` 은 다 이은 뒤에야 안다.

**따라오는 것:** 렌더러의 `@page` 바닥 여백은 **12mm 이상** — 쪽수가 들어갈 자리다.
(`render_drill_grammar` · `render_drill_tf` · `render_drill_vocab` · `render_mock_exam` 전부 12mm.)
글꼴은 Helvetica 9pt, 회색(#444), 밑선은 종이 아래 끝에서 6mm — 프린터 인쇄 불가 영역 밖.

**새 build_*.py 를 만들 때:** `from tools.pdf_pages import save_pdf` 로 저장한다.
Chrome 이 낸 PDF 를 그대로 쓰면 `stamp_file(pdf)` 한 줄을 붙인다.

## 2. 제목에 학년을 반드시 넣는다 (2026-09-27)

원장 지적: 동형 모의고사 PDF 를 열어 보니 제목이 `영일중 동형 모의고사 4세트`뿐이었다.
`중1`·`중2` 는 **파일명에만** 있고 내용(제목) 안에는 없었다 — 인쇄해서 낱장으로
돌면 몇 학년 것인지 알 길이 없어진다.

**강제 자리:** [`tools/render_mock_exam.py`](../tools/render_mock_exam.py) `build()` 의
`title` 인자. [`tools/build_mock_pdf.py`](../tools/build_mock_pdf.py) 가 파일명에 쓰는
문자열(`base` — 학교+학년+세트)을 그대로 넘긴다. 두 자리가 갈라지지 않도록 **같은
문자열을 재사용**한다 — 파일명과 내용 제목이 서로 다른 문구가 되지 않게.

새 build_*.py 를 만들 때: 파일명을 만드는 문자열을 렌더 함수에 그대로 넘겨 제목으로
쓴다. 파일명과 내용 제목을 따로 짓지 않는다.

## 3. 서술형은 지시문 · 제시 내용 · 보기 · 조건을 줄을 나눠 찍는다 (2026-10-04)

원장 지시: 「주관식 조건이나 내용 줄 때 줄바뀜 잘 이뤄져서 문서 포맷이 읽기 편하게」.
그 전 세트는 `<조건> ① … ② … ③ …` 을 한 줄에 이어 붙여, 세 번째 조건부터 아이가 놓쳤다.

    24. 다음 우리말을 <조건>에 맞게 영어로 쓰시오.        5점
       ┌ 제시 상자 — 우리말 문장 / 대화(발화당 한 줄) / Q: ┐
       [보기] watch  child  reach  balloon
       ┌ <조건>
       │ · 조건 하나에 한 줄
       │ · 단어 수: 6~8 단어
       └
       ________________________ (답 줄 2개, 답이 (a)(b) 로 나뉘면 4개)

**강제 자리:** 두 곳.
- [`pipeline/mock_exam.py`](../pipeline/mock_exam.py) 서술형 스키마 — `prompt_ko`(지시문 한 문장)
  · `context`(제시 내용, 줄바꿈) · `conditions`(배열, 항목당 조건 하나)를 **필수 칸으로 따로** 받는다.
  모델이 한 칸에 몰아 쓸 자리가 없다.
- [`tools/render_mock_exam.py`](../tools/render_mock_exam.py) `essay_html()` — 위 모양으로 찍는다.
  `essay_parts()` 가 옛 세트(한 칸에 몰아 쓴 것)도 `<조건>` · `①②③` · `·` 를 기준으로 쪼개
  같은 모양으로 만든다 — 괄호 안의 `·`(진행형·to부정사)는 자르지 않는다.

## 4. 서술형 답은 채점하기 쉽게 — 칸 하나에 몇 단어, 길어야 한 줄 (2026-10-04)

원장: 「줄줄이 줄글을 쓰도록 되어 있어 채점이 너무 힘들다. 영작을 시킨 다음 특정 번째 단어를
쓰게 하든가, 채점이 길어야 한 줄에 그치거나 몇 개 단어를 쓰게」.

    영작               문장은 완성하게 하되 답은 「3번째·6번째 단어」 만 — 위치는 노리는 어법 자리
    본문 질문에 답하기  문장 틀을 주고 빈칸 2~4단어
    틀린 곳 고쳐 쓰기   「기호 / 틀린 말 → 고친 말」 (문장 전체를 다시 쓰지 않는다)

**강제 자리:** [`pipeline/mock_exam.py`](../pipeline/mock_exam.py) — 지시문(SYSTEM)에 세 꼴을 적고,
스키마에 `answer_slots`(답칸)를 필수로 두고, `parse()` 가 **답 한 칸이 7단어를 넘으면 problems** 로
막는다 (「틀린 것 → 고친 것」 은 고친 쪽만, 「(… 도 정답)」 은 빼고 센다).
렌더러 `essay_html()` 은 `answer_slots` 가 있으면 줄 대신 「3번째 단어: ____」 칸을 찍는다.
이미 만든 영덕 1·2학년 세트는 [`tools/revise_essays_grading.py`](../tools/revise_essays_grading.py)
로 손으로 고쳤다 (원래 문항은 JSON 의 `revised_from` 에 남김).
