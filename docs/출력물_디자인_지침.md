# 출력물 디자인 지침

드릴·동형 모의고사·학습지 등 **종이로 나가는 모든 PDF** 에 적용한다.
원장이 정한 것을 번호로 쌓는다. 번호는 바꾸지 않는다 — 코드 주석이 `디자인 지침 1` 처럼 번호로 가리킨다.

지침은 **코드로 강제**한다. 사람이 기억해서 지키는 것이 아니라, 정해진 자리를 거치면
저절로 지켜지게 한다. 새 지침을 받으면 ① 여기에 적고 ② 그것을 강제하는 코드 자리를 적는다.

이미 출력해 나간 것은 다시 뽑지 않는다. 지침은 **그 뒤에 만드는 것부터** 적용한다.

---

## 1. 쪽수는 아래 가운데 — `n / N` (2026-09-18)

모든 출력물의 **모든 쪽** 아래 가운데에 `3 / 37` 꼴로 찍는다. 문제지·정답지 각각 따로 센다.

**강제 자리:** [`tools/pdf_pages.py`](../tools/pdf_pages.py) `save_pdf()` / `stamp_file()`.
PDF 를 파일로 내는 코드는 전부 이것을 거친다 — `writer.write()` 를 직접 부르지 않는다.

| PDF 를 내는 곳 | 거치는 함수 |
|---|---|
| `tools/build_school_drills.py` (학교 × 과 자체드릴) | `save_pdf` |
| `tools/build_drill_pdf.py` (드릴 종류별 8권) | `save_pdf` |
| `tools/build_mock_pdf.py` (동형 모의고사) | `stamp_file` |

**왜 HTML 이 아니라 PDF 단계에서 찍는가:** Chrome 은 `@page { @bottom-center }` 를
지원하지 않고, 기본 머리글·바닥글은 날짜·URL 이 붙어 못 쓴다. 게다가 한 권은 세트
여러 개를 따로 찍어 잇기 때문에 전체 쪽수 `N` 은 다 이은 뒤에야 안다.

**따라오는 것:** 렌더러의 `@page` 바닥 여백은 **12mm 이상** — 쪽수가 들어갈 자리다.
(`render_drill_grammar` · `render_drill_tf` · `render_drill_vocab` · `render_mock_exam` 전부 12mm.)
글꼴은 Helvetica 9pt, 회색(#444), 밑선은 종이 아래 끝에서 6mm — 프린터 인쇄 불가 영역 밖.

**새 build_*.py 를 만들 때:** `from tools.pdf_pages import save_pdf` 로 저장한다.
Chrome 이 낸 PDF 를 그대로 쓰면 `stamp_file(pdf)` 한 줄을 붙인다.

## 2. 제목에 학년을 반드시 넣는다 (2026-09-27)

원장 지적: 동형 모의고사 PDF 를 열어 보니 제목이 `영일중 동형 모의고사 4세트`뿐이었다.
`중1`·`중2` 는 **파일명에만** 있고 내용(제목) 안에는 없었다 — 인쇄해서 낱장으로
돌면 몇 학년 것인지 알 길이 없어진다.

**강제 자리:** [`tools/render_mock_exam.py`](../tools/render_mock_exam.py) `build()` 의
`title` 인자. [`tools/build_mock_pdf.py`](../tools/build_mock_pdf.py) 가 파일명에 쓰는
문자열(`base` — 학교+학년+세트)을 그대로 넘긴다. 두 자리가 갈라지지 않도록 **같은
문자열을 재사용**한다 — 파일명과 내용 제목이 서로 다른 문구가 되지 않게.

새 build_*.py 를 만들 때: 파일명을 만드는 문자열을 렌더 함수에 그대로 넘겨 제목으로
쓴다. 파일명과 내용 제목을 따로 짓지 않는다.

## 3. 서술형은 지시문 · 제시 내용 · 보기 · 조건을 줄을 나눠 찍는다 (2026-10-04)

원장 지시: 「주관식 조건이나 내용 줄 때 줄바뀜 잘 이뤄져서 문서 포맷이 읽기 편하게」.
그 전 세트는 `<조건> ① … ② … ③ …` 을 한 줄에 이어 붙여, 세 번째 조건부터 아이가 놓쳤다.

    24. 다음 우리말을 <조건>에 맞게 영어로 쓰시오.        5점
       ┌ 제시 상자 — 우리말 문장 / 대화(발화당 한 줄) / Q: ┐
       [보기] watch  child  reach  balloon
       ┌ <조건>
       │ · 조건 하나에 한 줄
       │ · 단어 수: 6~8 단어
       └
       ________________________ (답 줄 2개, 답이 (a)(b) 로 나뉘면 4개)

**강제 자리:** 두 곳.
- [`pipeline/mock_exam.py`](../pipeline/mock_exam.py) 서술형 스키마 — `prompt_ko`(지시문 한 문장)
  · `context`(제시 내용, 줄바꿈) · `conditions`(배열, 항목당 조건 하나)를 **필수 칸으로 따로** 받는다.
  모델이 한 칸에 몰아 쓸 자리가 없다.
- [`tools/render_mock_exam.py`](../tools/render_mock_exam.py) `essay_html()` — 위 모양으로 찍는다.
  `essay_parts()` 가 옛 세트(한 칸에 몰아 쓴 것)도 `<조건>` · `①②③` · `·` 를 기준으로 쪼개
  같은 모양으로 만든다 — 괄호 안의 `·`(진행형·to부정사)는 자르지 않는다.

## 4. 서술형 답은 채점하기 쉽게 — 칸 하나에 몇 단어, 길어야 한 줄 (2026-10-04)

원장: 「줄줄이 줄글을 쓰도록 되어 있어 채점이 너무 힘들다. 영작을 시킨 다음 특정 번째 단어를
쓰게 하든가, 채점이 길어야 한 줄에 그치거나 몇 개 단어를 쓰게」.

    영작               문장은 완성하게 하되 답은 「3번째·6번째 단어」 만 — 위치는 노리는 어법 자리
    본문 질문에 답하기  문장 틀을 주고 빈칸 2~4단어
    틀린 곳 고쳐 쓰기   「기호 / 틀린 말 → 고친 말」 (문장 전체를 다시 쓰지 않는다)

**강제 자리:** [`pipeline/mock_exam.py`](../pipeline/mock_exam.py) — 지시문(SYSTEM)에 세 꼴을 적고,
스키마에 `answer_slots`(답칸)를 필수로 두고, `parse()` 가 **답 한 칸이 7단어를 넘으면 problems** 로
막는다 (「틀린 것 → 고친 것」 은 고친 쪽만, 「(… 도 정답)」 은 빼고 센다).
렌더러 `essay_html()` 은 `answer_slots` 가 있으면 줄 대신 「3번째 단어: ____」 칸을 찍는다.
이미 만든 영덕 1·2학년 세트는 [`tools/revise_essays_grading.py`](../tools/revise_essays_grading.py)
로 손으로 고쳤다 (원래 문항은 JSON 의 `revised_from` 에 남김).

**예외 — 자유 서술 한 문장 (2026-11-15):** 영일중1 2026 기말 논술이 「글 내용을 한 문장으로 · 본문 연속 3단어 금지」 로 나왔다
([판독](../data/stage0/comparisons/중1_영일_2026기말_기출.md) §3). 학교가 줄글을 요구하면 그 꼴로 연습시켜야 한다.
설계도에 `essay_free: n` 이 있는 학교만, n 문항까지, 답칸 없이 16단어 이하 한 문장을 허용한다 (`parse()` 가 센다).
채점이 흔들리지 않게 정답지에 **감점표와 자주 나오는 감점 답**을 찍는다 — [`tools/make_essay_drill.py`](../tools/make_essay_drill.py) 가 그 꼴이다.

## 5. 정답지 맨 위에 정답표 (2026-10-04)

원장 지적: 동형 모의고사 정답지는 해설 속에 정답이 흩어져 있어 **채점할 때 매우 불편**했다.
정답지 첫 쪽, 제목 바로 아래(해설 앞)에 정답만 나열한 표를 둔다. 원장이 보여 준 기존 정답표 꼴:

    번호     |            |
    01~10번  | ④②②③②  | ⑤①②⑤⑤
    11~20번  | ③③②③③  | ③②①④① 

10문항씩 한 줄, 5개씩 두 칸. 그 아래 서술형은 한 문항 한 줄에 **답 자체**를 적는다
(「(완성 문장: …)」 은 해설 쪽에만). 서술형이 1번부터 다시 세는 세트(중1 5과 1~3)는 `서술형 1번`.
~~서술형은 칸에 `주`~~ — 원장: 「주라고 표기하지 말고 답을 써 줘야지」. 채점용 표다 (2026-10-04).

~~처음에는 정답지 앞에 「정답 모아보기」 한 쪽(큰 격자 + 서술형 답)을 따로 끼웠다~~ — 원장이
말한 것은 해설 위에 붙는 작은 정답표였다. 한 쪽을 통째로 넣는 꼴은 버렸다 (2026-10-04).

**강제 자리:** [`tools/render_mock_exam.py`](../tools/render_mock_exam.py) `quick_key()` —
`build()` 가 `part="answers"` 일 때 머리 바로 뒤에 붙인다. `build_mock_pdf.py` 로 뽑는
정답지는 저절로 들어간다.

**이미 나간 정답지에 넣을 때:** JSON 으로 정답지만 다시 뽑되, **먼저 다시 뽑은 시험지를 Z: 에
있는 시험지와 글자 대조**한다. 2026-10-04 영덕중1 5·6과 5세트는 PDF 를 낸 뒤 JSON 의 12번
보기 순서(②↔⑤)가 바뀌어 있었다 — 그대로 뽑았으면 학생 시험지와 정답이 어긋났다.
이미 학생들에게 인쇄해 나간 시험지가 기준이므로 JSON 을 Z: 시험지 순서(정답 ②)로 되돌렸다
(원장 2026-10-04). 되돌린 JSON 으로 뽑은 시험지·정답지가 Z: 와 글자 단위로 같음을 확인.
적용: 영덕중1 5·6과 4~6세트 · 영덕중2 1~6세트 (원본은 각 폴더 `_원본(모아보기 전)/`).

## 6. 부정 발문은 밑줄·굵게 (2026-11-04)

「어법상 **틀린** 것은?」 「일치하지 **않는** 것은?」 「쓰임이 **다른** 것은?」 — 부정어를 놓치면 아는 문제도
틀린다. 실제 내신 시험지도 밑줄을 친다. 그때까지 32세트의 부정 발문 188개 중 강조된 것은 13개였다
(모델이 `**` 를 넣었다 말았다 했고, 렌더러는 그것도 그대로 찍었다).

**강제 자리:** [`pipeline/item_principles.py`](../pipeline/item_principles.py) `NEG` (부정어 + 뒤에 「것·곳·말·문장…」) →
[`tools/render_mock_exam.py`](../tools/render_mock_exam.py) `stem_html()` 이 선택형 발문과 서술형 지시문에
`<span class="neg">` (밑줄 + 굵게) 를 씌운다. 발문 데이터는 손대지 않는다 — 찍을 때만.

**왜 렌더러인가:** 모델에게 「강조하라」 고 맡기면 세트마다 들쭉날쭉하다. 찍는 자리 하나를 거치면 옛 세트를
다시 뽑아도 똑같이 나온다 (글자·순서는 그대로이므로 Z: 대조에 걸리지 않는다).

## 7. 보기 · 대화 · 지문은 줄을 나눠 찍는다 (2026-11-08)

원장: 「시험지 만들 때 왜 줄바꿈이 하나도 안 되어 있지? 너무 읽기 불편하다. 보기나 선택지 줄 때 반드시 줄바꿈」.
세어 보니 동형 자료 471개 중 500자 넘는 지문 92개가 줄바꿈 0 — 교과서 본문(`body_text`)이 한 줄로 저장돼
「Challenge 01 Reduce Food Waste Olivia: My birthday…」 가 한 덩어리로 찍혔다. 발문 속 <보기>도 26개가
줄바꿈 없이 들어와 있었다.

- **<보기> 항목** (a. b. / (A) (B) / [1] [2] / ① ②) 은 항목 하나에 한 줄. 「<보기>」 표시 다음 줄부터.
- **대화**는 발화 하나에 한 줄, **화자 · 소제목** 앞에서 줄을 바꾸고 소제목 · 화자 이름 줄은 굵게.
- **단락**이 있는 글은 단락마다 줄을 바꾼다. 교사 자작 단락처럼 원래 한 단락인 짧은 글은 그대로.
- **선지**는 원래 한 줄에 하나 (`ol.opt`).

**강제 자리:** [`pipeline/layout.py`](../pipeline/layout.py) `break_positions()` 가 줄 바꿀 **자리만** 계산한다
(화자 `Olivia:` · 소제목 `Challenge 01` · 보기 항목 앞이 문장 끝일 때 + 손으로 적은 `breaks`).
[`pipeline/underline.py`](../pipeline/underline.py) `html_with_underline()` 이 그 자리의 공백을 줄바꿈으로 찍고,
발문은 `layout.split_lines()` 를 거친다 (시험지 [`render_mock_exam.py`](../tools/render_mock_exam.py) · 결과지
[`build_report_card.py`](../tools/build_report_card.py) 둘 다). 기계가 단락을 모르는 지문은
[`data/stage0/passage_breaks.json`](../data/stage0/passage_breaks.json) 에 「이 글 앞에서 줄 바꿈」 을 적는다.
생성 프롬프트(`pipeline/mock_exam.py`)도 같은 규칙을 지시하고, `item_principles.check()` 가 600자 넘게 줄 나눔이
없는 자료를 경고한다.

**왜 글자를 안 바꾸나:** 본문은 확정 후 불변(설계 7)이고 밑줄·태그가 글자 위치에 걸려 있다. 밑줄처럼
「찍을 때만」 바꾸면 옛 세트를 다시 뽑아도 글자는 그대로다.
