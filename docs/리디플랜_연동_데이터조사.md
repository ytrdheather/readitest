### 리디플랜 분석기의 「고르기 목록」으로 충분한가

리디플랜 분석기는 지금 `grammar_point` 를 **자유 텍스트**로 받습니다(`api/examAnalyzerModule.js:56`, 예:
「관계대명사 계속적 용법」「가정법 과거완료」).

- **중학교 시험이면 대체로 충분합니다.** 4개교 96문항 전수 분류를 이 목록으로 했고, 기출 근거 28행이
  전부 기존 코드로 들어갔습니다.
- **빈칸** — 2026-1 기말에서 실제로 코드에 딱 맞지 않았던 것:
  - 「의문사 + 조동사 어순 / 미래 표현」(영덕 4번) → 대응 코드 없음
  - 「비인칭 it vs 대명사 it」 → `IT_CLEFT` 에 가주어·강조구문과 함께 묶여 있음
  - 「조건절 미래시제」 → `VERB_TENSE` 로 들어감 (라벨은 「시제 일치」라 학부모가 읽기엔 어긋남)
  - 「주격 관계대명사 who」 → `REL_PRON_VS_ADV` 로 들어감
  - 중1 범위: `be going to`, 명령문, 과거시제, `There is/are` → 대응 코드 없음 (중1 동형 서술형
    `target_grammar` 에 「be going to (미래 표현)」이 자유 텍스트로 나옴)
- **고등학교 시험에는 부족합니다.** 분사구문, 가정법 세부(과거/과거완료/혼합), 간접의문문, 강조 do 등이
  없거나 한 코드로 뭉쳐 있습니다. `SUBJUNCTIVE` 하나에 가정법 전체가 들어갑니다.
- **라벨이 내부용입니다.** `VERB_MODAL_USAGE` 의 라벨이 「have to / must / don't have to」라
  학부모 리포트 문구로는 다듬어야 합니다.

→ 권장: 리디플랜은 **코드를 고르게 하되 「목록에 없음 + 자유 텍스트」를 함께 허용**하고, 자유 텍스트로
들어온 것을 모아 리디테스트 쪽 후보 코드로 올리는 흐름이 맞습니다. 목록을 리디플랜이 독단으로
늘리면 두 시스템의 코드가 갈립니다(기획서: 「자유 텍스트 금지 — 시스템의 어휘」).

## 7. 뷰 SQL 초안 — **실행하지 않았습니다**

> 🔴 아래는 **초안**입니다. `create view` · `grant` 는 원장 확인 뒤에 SQL Editor 에서 실행합니다.
> **`DROP` / `DELETE` / `TRUNCATE` 는 포함되어 있지 않습니다.** `create or replace view` 와 `revoke`/`grant` 만 있습니다.
> 기존 테이블·행은 건드리지 않습니다.

### 7-1. 학교 × 어법 포인트 출제 이력 + 시험일

```sql
-- report_school_grammar : 리디플랜 학부모 리포트용. 읽기 전용.
-- 한 행 = 학교 × 학년 × 어법 포인트.
-- exam_hit_count 는 「기출에서 확인된 시험 수」, exams_observed 는 그 학교·학년의 관측 시험 수(분모).
-- 둘을 함께 보여줘야 「1회 중 1회」를 「단골」로 오독하지 않는다.
create or replace view report_school_grammar
with (security_invoker = false)          -- 뷰 소유자 권한으로 기반 테이블을 읽는다 (§8 참고)
as
select
  s.name                                              as school_name,       -- '영덕중'
  m.grade,
  tb.label                                            as textbook,
  m.grammar_point_code,
  gp.label_ko                                         as grammar_label_ko,
  gp.category                                         as grammar_category,
  gp.is_candidate                                     as grammar_is_candidate,
  count(distinct m.evidence_exam_id)                  as exam_hit_count,
  (select count(*) from exam e2
    where e2.school_id = m.school_id and e2.grade = m.grade)
                                                      as exams_observed,
  count(*) filter (where m.evidence_exam_id is null)  as handout_scope_rows, -- 배부물(이번 학기 범위) 근거
  min(e.exam_date)                                    as first_hit_exam_date,
  max(e.exam_date)                                    as last_hit_exam_date,
  string_agg(distinct (e.year || '-' || e.semester || ' ' || e.sitting), ', ')
                                                      as hit_exams,          -- '2026-1 기말'
  string_agg(distinct m.textbook_unit, ', ')          as units,              -- 'Lesson 3-4, Lesson 5'
  max(m.updated_at)                                   as updated_at
from school_grammar_map m
join school        s  on s.id    = m.school_id
join grammar_point gp on gp.code = m.grammar_point_code
left join textbook tb on tb.id   = m.textbook_id
left join exam     e  on e.id    = m.evidence_exam_id
group by s.name, m.school_id, m.grade, tb.label,
         m.grammar_point_code, gp.label_ko, gp.category, gp.is_candidate;
```

`note` 는 뷰에 넣지 않았습니다 — 내부 판단 메모(「원장 판단 필요」 등)가 섞여 있어 학부모 리포트로 새면 안 됩니다.

### 7-2. 시험 일정

```sql
create or replace view report_exam_schedule
with (security_invoker = false)
as
select s.name as school_name, e.grade, e.year, e.semester, e.sitting, e.exam_date,
       e.mc_count, e.essay_count, e.total_score
from exam e join school s on s.id = e.school_id;
```

### 7-3. 권한 (1안 기준)

```sql
revoke all on report_school_grammar, report_exam_schedule from public, anon, authenticated;
grant select on report_school_grammar, report_exam_schedule to anon;
```

## 8. 리디플랜에서 읽는 키 방식 — 제안 (키 값은 다루지 않음)

현재 RLS: 모든 테이블이 기본 거부, 정책은 원장(`is_director()`)과 직원(`is_staff()`)용뿐입니다.
anon 키로 `school`·`exam`·`grammar_point`·`school_grammar_map`·`exam_observation`·`item` 을 조회하면
**전부 HTTP 200 · 0행**이었습니다 — 의도대로 막혀 있습니다.

| | 1안 (권장, 단순) | 2안 (더 좁음) |
|---|---|---|
| 리디플랜이 쓰는 것 | `SUPABASE_URL` + **publishable(anon) 키** | URL + publishable 키 + **리디플랜 전용 로그인 계정** |
| 열리는 범위 | §7 의 **보고서용 뷰 두 개만** `grant select to anon`. 기반 테이블 RLS·정책은 그대로 | 뷰 안에 `where is_staff()` 를 넣고 `grant select to authenticated`. 전용 계정을 `profile` 에 `assistant` 로 등록 |
| 장점 | 테이블 정책을 하나도 안 바꿈. 뷰에 학생 정보·지문·내부 메모가 없음 | 키가 새도 계정 없이는 못 읽음 |
| 단점 | publishable 키는 원래 공개 전제라, 키와 URL 을 아는 사람은 집계표(학교·코드·날짜)를 읽을 수 있음 | 계정 관리·토큰 갱신 코드가 리디플랜에 필요. `security_invoker=false` 뷰라 Supabase 린터 경고가 뜸(1안도 동일) |

공통 원칙:

- 🔴 **리디플랜에 `service_role`(secret) 키를 넣지 않습니다.** RLS 를 우회하고 쓰기까지 됩니다.
- 키는 리디플랜 **서버 `.env`** 에만 두고 브라우저로 내려보내지 않습니다 (리디플랜 Node 서버가 대신 조회).
- 키는 컴퓨터마다 새로 발급하고 카톡·메일로 옮기지 않습니다 (CLAUDE.md 규칙 2).
- 리디플랜은 **쓰기 경로가 없어야 합니다** — 뷰는 집계(group by)라 원래 쓸 수 없지만, 기반 테이블에 anon
  쓰기 정책을 만들지 않는 것으로 이중으로 막습니다.
- `security_invoker = false` 는 의도된 것입니다. `true` 로 하면 anon 에게 기반 테이블 select 정책을 열어야 하고,
  그러면 `note` 같은 내부 컬럼까지 보입니다.

## 10. 부족한 점과 다음 할 일

### 부족한 점

1. **반복 관측이 없고, 쌓을 구조도 아직 아닙니다.** 학교당 기출 1회(영덕 2회). map 적재 스크립트가 (학교, 코드)로
   중복을 걸러 2회째 관측을 버립니다 (§3 🔴 — 영덕 to부정사가 실제로 이렇게 빠졌습니다). 「단골 포인트」는 2026-2 중간(9/29~10 둘째 주)
   기출이 들어온 뒤에야 처음으로 2회째가 생깁니다. 그때도 단원이 다르므로(L3-4 vs L5-6) 포인트 겹침은 적을 것입니다.

4. **문항 수·배점이 map 에 컬럼으로 없습니다** (`note` 자유 텍스트).
5. **대비 자료가 DB 에 없습니다.** 어법 드릴만 파일 안에 코드가 붙어 있습니다.
6. **중1 지문이 중2 교과서 ID 로 들어가 있습니다** (§5 ⚠️).
7. `grammar_point` 후보 7종이 아직 승인 전이고, 고등 범위는 비어 있습니다.
